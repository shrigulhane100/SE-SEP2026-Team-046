# Rock Starz – Scrum Planning

## 1. Introduction

Team "Rock Starz" follows an Agile Scrum-inspired project management approach to organise development, distribute responsibilities, monitor progress and review deliverables.

The project consists of five milestones, with two primary development sprints. M2 acts as the pre-sprint preparation phase, while M5 serves as the post-sprint finalisation phase.

GitHub Projects is used to manage tasks, assignments, priorities, deadlines and progress. GitHub Issues and Pull Requests are used to coordinate individual contributions and review code changes.

## 2. Project Execution Model

| Phase | Milestone | Focus |
|---|---|---|
| Requirements Identification | M1 | User research and requirements identification |
| Pre-Sprint Preparation | M2 | Project planning, team organisation, system design and frontend preparation |
| Sprint 1 | M3 | Backend development and database integration |
| Sprint 2 | M4 | Application integration, testing and deployment |
| Post-Sprint Finalisation | M5 | Final documentation, verification, demonstration and release |

M1 establishes the initial requirements. M2 prepares the project for implementation. M3 and M4 form the two main development sprints, followed by M5 finalisation.

## 5. Development and Collaboration Workflow

The team follows a branch-based Git workflow.

1. Work is recorded as GitHub Issues with objectives and acceptance criteria.
2. Tasks are assigned to the responsible team members.
3. Contributors create task-specific branches.
4. Changes are committed and pushed to the repository.
5. Pull Requests are opened against the main branch.
6. Technical review and testing are performed before merging.
7. GitHub Projects is updated to reflect the current task status.

The project board uses the following statuses:

- Backlog
- Todo
- In Progress
- In Review
- Done

## 6. Quality Assurance and Review

Quality assurance is carried out throughout development.

- Contributors verify their work against the issue acceptance criteria.
- Backend unit testing is performed during Sprint 1.
- Independent API and application testing is conducted by the tester.
- Technical review is performed before milestone submission.
- Integration and regression testing are conducted during Sprint 2.
- Final documentation and demonstration materials are verified during M5.

## 7. Milestone Completion Process

Each milestone follows a common completion workflow:

1. Complete the assigned implementation and documentation tasks.
2. Verify the deliverables against milestone requirements.
3. Conduct technical review.
4. Address identified issues and review feedback.
5. Consolidate the final deliverables.
6. Complete milestone submission.

The Project Manager coordinates documentation and submission, while the designated Code Reviewer performs the technical review.

## 8. Schedule Management
